## 1. 왜 하는가

현재 도구는 **증상 개수만 세고 나머지 진단기준을 보지 않는다.**

`js/data.js`의 `duration`(기간)·`other`(배제·부가 기준)는 줄글이라 자동 채점에서 빠져
있다(README에 명시). 그 결과 **우울 증상 5개가 체크되면 그것이 2주짜리든 이틀짜리든
똑같이 "기준 충족 가능성"으로 표시된다.** DSM-5-TR은 2주 이상을 요구하는데도 그렇다.

이 트랙은 기간·연령·빈도·기능손상을 기계가 판정할 수 있는 형태로 바꿔 채점에 넣는다.
**판정 결과 자체가 달라지므로 도구의 정확도가 직접 올라간다.**

동시에 화면을 채팅 틀로 되돌린다(§4). 위저드 형식보다 사용자가 선호하는 형태이고,
문답 이력이 위로 쌓여 지나온 판단을 되짚기 쉽다.

## 2. 승계하는 원칙 (선행 트랙에서 확정, 변경 금지)

이 트랙의 모든 결정은 아래를 깨뜨리지 않는다. 하나라도 충돌하면 이 목록이 우선한다.

**도구의 성격**
1. 상담사가 관찰·보고를 바탕으로 **스스로 판단해 체크**하는 임상 보조 기록 도구
   (SCID와 같은 위치). 내담자 자가진단 도구가 아니다.
2. 모든 질문은 "상담사가 답하는 문항"으로 쓴다.
3. 임상가를 대체하지 않는다 — 경고 문구를 화면과 내보내기 파일에 상시 노출한다.

**판정의 안전 원칙**
4. **"확인 안 됨"을 "아니오"로 취급하지 않는다.**
5. **어떤 진단도 목록에서 제거하지 않는다.** 미충족·미확인은 순위와 표시에만 반영한다.
6. 자동 배제(exclusion) 기능을 만들지 않는다 — 감별진단은 임상가의 몫이다.
7. 미체크 항목은 "증상 없음"이 아니라 **"미확인"**으로 표시한다.
8. 문진은 전 문항을 순회한다. 중간 건너뛰기를 넣지 않는다.

**콘텐츠 출처**
9. 질문·규칙은 `data.js`에서 도출한다. 새 임상 판단을 창작하지 않는다.
10. 소견 키워드 매칭은 **순서 정렬 전용**이다. 배제에 쓰지 않고, 근거를 표시하며,
    기본 순서로 되돌릴 수 있다.

**AI**
11. AI 호출은 결과당 **1회**뿐이다.
12. AI는 판단·계산·후보 좁히기를 하지 않는다. 확정된 결과의 서술만 한다.
13. **AI 없이도 도구가 완전히 작동한다.**
14. 프롬프트 상한: 후보 상위 5개, 체크된 근거만, 기준 전문 미포함.

**저장·배포**
15. 진행 상태는 `sessionStorage`만 쓴다(`localStorage` 금지 — 공용 PC에 내담자 정보 잔존).
16. "처음부터 다시" 버튼을 항상 제공한다.
17. 내담자 정보를 서버로 전송하지 않는다.
18. 파일로 직접 열어도(`file://`) AI를 제외한 전 기능이 동작해야 한다
    → 문답·판정 코드는 **일반 스크립트(비-module)**로 작성한다.
19. 공개 배포 유지 + 링크 선별 안내 + `noindex` + 경고 문구. Cloudflare 이전은 보류.

**작업 방식**
20. 원문 대조·동치·브라우저 스모크 테스트로 검증한다.
21. 테스트 스크립트는 저장소에 커밋하지 않는다(스크래치패드에서 실행).
22. **커밋·푸시는 사용자의 명시 지시가 있을 때만 한다.**

## 3. 단계 구분

| 단계 | 내용 | 화면 변화 |
|---|---|---|
| **1** | 게이트 개정 + `rules` 데이터 + 판정 엔진 + 테스트 | **없음** |
| **2** | 채팅 틀 문답 화면으로 교체, 위저드 화면 제거 | 전면 교체 |
| **3** | 증상 항목 4분류 **라벨**(생각/행동/감정/신념) | 항목 옆 표시 추가 |

1단계에 화면 변화가 없는 것은 의도적이다. 판정 로직과 화면을 동시에 바꾸면 결과가
이상할 때 어느 쪽 문제인지 가릴 수 없다. 1단계를 테스트로 보증한 뒤 2단계에 들어간다
(선행 트랙에서 채점 로직을 먼저 분리·검증하고 화면을 만든 것과 같은 방식).

## 4. 화면 요구사항 (2단계)

### 4.1 틀은 `chat.html`의 레이아웃을 쓴다

사용자가 이 레이아웃을 선호한다. 위저드의 "한 화면에 질문 하나 + 진행률 바" 형식은 없앤다.

```
┌────────────────────────────────┬──────────────────┐
│ 대화 영역 (말풍선이 위로 쌓임)     │ 경고 문구          │
│                                │                  │
│  후투티: 소견을 적어주세요          │ 유력한 진단        │
│  상담자: 3개월 전 퇴사 후…         │  1. 주요우울장애    │
│  후투티: [문항 1] 우울한 기분이…    │     증상 ✓ 기간 ✓  │
│          [예][아니오][확인 안 됨]   │     기능손상 미확인 │
│  ...                           │  2. …            │
├────────────────────────────────┤                  │
│ 입력창 (소견 입력 전용)            │ [결과 저장]        │
│ [처음부터 다시] [AI 선택] …        │                  │
└────────────────────────────────┴──────────────────┘
```

### 4.2 대화 흐름

1. 인사 + 소견 요청 → **입력창은 이 단계에서만 사용**한다(건너뛰기 가능)
2. 게이트 문항을 말풍선으로 하나씩 제시 → 말풍선 안의 버튼으로 답변
   (답한 말풍선은 선택 결과를 표시한 채 위에 남는다 → 되짚어 보기·수정 가능)
3. **정밀 체크리스트를 대화 흐름 안 말풍선으로 제시** — 걸린 범주의 진단 항목을
   체크박스 묶음으로. "아니오" 범주는 접힌 채로 함께 제시하되 삭제하지 않는다.
4. 정량 질문(기간·연령·빈도·기능손상)을 말풍선으로 제시 — **상위 후보에 대해서만**
   묻는다(§6.3 문항 폭발 방지)
5. **AI 설명이 마지막 말풍선으로** 출력된다. 별도 출력 영역을 만들지 않는다.

### 4.3 오른쪽 패널

내내 실시간으로 갱신되며, 각 후보에 **축별 판정 배지**를 붙인다
(충족 / 미달 / 미확인 / 자동판정 불가).

### 4.4 기존 화면 처리

- 위저드 화면(`index.html` 3단계 마크업, `js/wizard.js`, 위저드 전용 CSS) → **제거**
- `chat.html`(자유 대화) → **남긴다**. 되돌릴 경로이자 자유 서술이 필요한 경우용.
  다만 메뉴에서 눈에 덜 띄게 둔다.
- `checklist.html`(81개 직접 탐색) → 그대로 유지

## 5. 정량 판정 요구사항 (1단계 핵심)

### 5.1 판정 축

| 축 | 내용 | 비고 |
|---|---|---|
| 증상 | 항목군 min·groupLogic (기존) | `scoring.js` 그대로 |
| 기간 | 최소·**최대** 둘 다 | 조현양상장애(1~6개월) 등 상한이 감별의 핵심 |
| 연령 | 발병/진단 연령의 최소·**최대** 둘 다 | 반사회성(18세 이상) 같은 하한이 존재 |
| 빈도 | 횟수/기간 또는 정성 수준 | "주 3회", "주 1회", "대부분의 날에" |
| 기능손상 | 있음/없음 | `other`의 "뚜렷한 지장" 조항 |
| 하루 소요시간 | 강박장애 전용 | **기간과 별개 축**(§5.3 ①) |

### 5.2 상태는 5가지

| 상태 | 의미 | 화면 |
|---|---|---|
| `PASS` | 충족 | 초록 |
| `FAIL` | 미충족 | 주황 (숨기지 않음) |
| `UNKNOWN` | 상담사가 아직 입력하지 않음 | 회색 |
| `QUALITATIVE` | 애초에 자동 판정 대상이 아님 | 파랑 "직접 확인 필요" |
| `NA` | 그 진단에 해당 규칙이 없음 | 표시하지 않음 |

`UNKNOWN`과 `QUALITATIVE`를 반드시 구분한다 — 전자는 "물어보면 채울 수 있음",
후자는 "물어봐도 자동으로는 못 정함"이라 상담사가 할 일이 다르다.

**종합 규칙**: 하나라도 `FAIL`이면 `FAIL` / `FAIL` 없고 `UNKNOWN`이 있으면 `UNKNOWN` /
전부 `PASS`·`NA`면 `PASS`. `NA`는 종합에서 제외한다(없는 규칙을 통과로 세지 않는다).

### 5.3 외부 문서의 결함 9건 — 정정 내용

2026-08-16 `data.js` 원문 대조로 확인한 것이다. 외부 문서를 그대로 구현하면 안 된다.

| # | 결함 | 근거(원문) | 정정 |
|---|---|---|---|
| ① | 강박장애의 "1시간"을 지속기간으로 넣음 | "하루 1시간 이상을 **소요**하는 등 시간소모적임" | 기간이 아니라 **하루 소요시간** 축으로 분리. 기간 축은 규칙 없음(`NA`) |
| ② | 적응장애의 "6개월"을 기간 상한으로 넣음 | "스트레스 요인 **종료 후** 6개월 이내 소실" | 지속기간 상한이 아님 → **정성(`QUALITATIVE`)으로 이동** |

| ⑦ | 미확인과 정성 판정을 뭉갬 | — | `UNKNOWN`/`QUALITATIVE` 분리(§5.2) |

| ⑨ | 연령별 분기·예외·복합조건 미표현 | 분리불안(성인 6개월/소아 4주), 지속성우울·순환성(성인 2년/소아 1년), 제1형 양극성("입원이 필요할 정도면 기간 무관"), 유뇨증("3개월 연속 주 2회") | 연령 분기·예외 조항·복합 조건을 스키마가 표현하도록 설계 |

### 5.4 단위 비교 규칙 (④ 정정)

일수로 환산하지 않는다. 같은 계열끼리 비교하고, 계열이 다르면 **정확한 환산 계수만** 쓴다.

- `years ↔ months`: 1년 = 12개월 (정확)
- `weeks ↔ days`: 1주 = 7일 (정확)
- `months ↔ days`: **부정확** → 이 조합이 필요한 규칙은 입력 단위를 규칙 단위에 맞춰
  받는다(예: "3개월 이상" 규칙이면 선택지를 개월 단위로 제시)

입력 UI가 규칙과 같은 단위를 쓰도록 설계해 환산 자체를 최소화한다.

### 5.5 정량 대상 46개 (48에서 조정)

외부 문서의 48개 분류는 `data.js`와 대조해 **분류·수치 모두 정확함을 확인**했다
(허구 ID 0건, 누락 0건, 수치 불일치 0건). 다만 §5.3 ①②에 따라 2개를 정성으로 옮긴다.

- 제외: `ocd-ocd`(하루 소요시간은 별도 축), `trauma-adjustment`(6개월은 기간 상한이 아님)
- 결과: **정량 46개 / 정성 35개**

`ocd-ocd`는 기간 축만 정성이고 하루 소요시간 축은 정량이다 — 축별로 다를 수 있으므로
`is_quantifiable`을 진단 단위 하나의 불리언으로 두지 않고 **축별로 판단**한다.

### 5.6 계산 불가 조건은 문구로 남긴다

"2개월 이상 증상 없는 기간이 없음"(지속성우울장애), "12개월간 3개 이상 & 6개월간 1개
이상"(품행장애) 같은 중첩 조건은 이번 범위에서 계산하지 않는다. 대신 규칙에 안내 문구
필드를 두어 화면에 **"추가로 확인할 것"**으로 표시한다. 조용히 통과시키지 않는다.

## 6. 게이트 개정 (1단계에 포함)

### 6.1 현재 22문항을 23문항으로

외부 `gates.js` 초안을 검증한 결과 **인용문 53개가 전부 `data.js`에 실재**했고
(날조 0건) 커버리지도 완전했다. 다만 통째 교체는 하지 않는다 — 아래 이유 때문이다.

**흡수할 것**
- **ADHD를 단독 게이트로 분리** (22 → 23문항). 가장 흔한 의뢰 사유이고 다른
  신경발달장애와 증상 성격이 다르다.
- **`source_items` 필드 도입** — 각 게이트가 `data.js`의 어느 항목에서 나왔는지 코드에
  근거를 남긴다. 임상 자문을 받을 때 그대로 검토 자료가 된다.

**흡수하지 않을 것**
- 외부 초안은 게이트마다 **범주 내 대표 진단 1~2개만 반영**해, 나머지가 질문에서 빠졌다.
  실측된 누락: 불안장애 게이트에 **공황발작 없음**(공황장애·광장공포증 단독 사례를
  놓칠 수 있음), 섭식 게이트에 이식증·회피적 제한적 섭취 없음, 신체증상 게이트에
  전환장애·인위성장애 없음, 외상 게이트에 적응장애·애착장애 없음.
  → 현재 게이트의 "범주 전체를 훑는" 설계를 유지한다.
- 지적발달장애를 자폐와 묶고 게이트를 "사회적 상호작용"으로 잡은 구성. 지적발달장애의
  핵심은 지적·학습 기능이라 사회성이 두드러지지 않은 사례를 놓칠 수 있다.
- 배설 게이트 질문에 박힌 "4~5세 이상" — 연령은 `rules`가 처리한다. 질문에 넣으면
  중복이고, 연령을 모르는 상담사가 "아니오"를 누를 위험이 있다.
- 한 문장에 조건 3~4개를 묶은 긴 질문 형식.

### 6.2 문구 정정 1건

외부 초안이 `pd-ocpd` 항목을 "규칙·목록·순서에 지나치게 집착함"으로 축약했는데,
원문은 "집착**해 정작 활동의 큰 흐름을 놓침**"이다. 기준의 핵심이 빠졌으므로
현재 게이트 문구를 점검해 같은 축약이 있으면 바로잡는다.

### 6.3 정량 질문은 상위 후보에만 묻는다

게이트 23문항 뒤에 기간·연령·빈도·기능손상을 81개 진단마다 물으면 문항이 폭발한다.
**증상 체크로 좁혀진 상위 후보에 대해서만** 묻는다.

- 연령은 내담자당 **한 번만** 묻는다(모든 진단이 공유).
- 기간·빈도·기능손상은 **후보별로** 묻는다 — 공존 진단에서 우울이 3개월, 불안이 5년일
  수 있어 공통 질문 하나로 판정할 수 없다.
- 답하지 않은 축은 `UNKNOWN`으로 남는다. 강제하지 않는다.

## 7. 증상 4분류 라벨 (3단계, 후순위)

외부 문서가 제안한 생각/행동/감정/신념 분류를 **라벨로만** 적용한다.

- **탭 필터로 만들지 않는다.** 필터는 분류가 틀린 항목을 화면에서 숨겨 false negative를
  만든다 — 이 트랙이 지키는 원칙 5·7과 정면으로 충돌한다.
- 라벨은 항목 옆 작은 표시일 뿐이며 **어떤 항목도 숨기지 않는다.** 분류가 틀려도
  손해가 "라벨이 어색함"에서 끝난다.
- 애매한 항목은 억지로 분류하지 않고 **무라벨**로 둔다.
- 대상: 395개 항목. 채점에는 영향을 주지 않는다.

**효과에 대한 정직한 평가**: 이 분류는 채점을 바꾸지 않으므로 정확도를 직접 올리지
않는다. 기대 효과는 간접적이다 — 상담사가 생각·행동·감정을 나눠 물으면 빠뜨리는
증상이 줄어들 수 있다. 그래서 정량화(직접 효과)보다 뒤에 둔다.

## 10. 승계되는 미해소 리스크

1. 게이트·체크리스트 문구가 임상 전문가 미검증(`data.js` 자체의 한계).
